# Hermes explorer semantic audit

Audit date: 2026-10-04. Source commit: `ddc0e65958b326a89f6c440c76c812d31ac27e2a` (clean checkout). This audits the represented CLI/generic-loop/app-server surface, not the entire Hermes application. Original `docs/research/context-lifecycles/hermes.md` remains unchanged.

## Later coverage expansion

This ledger preserves the 2026-10-04 audit snapshot of 51 architecture nodes and
91 relationships. The [expanded Hermes source study](../hermes.md) records
subsequent additions separately. Those new items are not covered by the status
counts in this original ledger.

## Status meaning

- **verified**: the stated surface relationship or contract was inspected in source and its caller. Not a claim about all internal branches or runtime outcomes.
- **corrected**: source inspection required changing the displayed claim, anchor or path assumption.
- **needs-deeper-review**: the represented owner exists, but its broad internals or external contract remain incompletely audited. Its current claim is bounded accordingly.

## Corrections and missing topology

1. Tool scheduling named only the sequential executor. Actual `_execute_tool_calls` plans parallel segments and sequential barriers; label, explanation and source anchors corrected.
2. Delegation appeared universally synchronous. Top-level model dispatch asks for background, while nested orchestrators join; consumer/capacity gates may fall back inline. Joined example now assumes one-shot CLI. Detached handle and later-completion relationships added.
3. Entry interrupt incorrectly pointed at `handle_api_interrupt`. Entry stops flow to generic finalization; provider-call interruption alone uses that handler.
4. Tool persistence descriptions implied universal durability. A missing/disabled store returns `None`, which callers accept because they check `is False`; descriptions now distinguish checked flush from durable SQLite write.
5. Memory sync described only detached work. Executor failure can run inline; notes corrected.
6. Native projection implied durable success. Failed flush is logged and dedicated finish can still return delivered output; publication of thread binding remains gated.
7. Facade cleanup described every failure. The admission try/finally excludes setup before the try; scope qualified.
