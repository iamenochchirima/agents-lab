## Scope and integration notes

- GatewayRunner is a separate host controller from CLIChatTurnMixin. Connect its TurnRunner.run_sync to the existing `turn-facade` through AIAgent.run_conversation. Do not connect gateway ingress to `cli-chat`.
- `init-agent` bridges mean common AIAgent initialization reached by constructor, not a call to CLI `_init_agent`. This distinction is included in each edge condition.
- An adapter callback topology edge means a transport produces normalized MessageEvent and calls base handler; it is not proof every concrete platform takes precisely the same ingress path. API-server/raw-session paths can bypass push adapter semantics.
- Two per-session guards have distinct owners: adapter task guard is installed before background-task spawn; GatewayRunner claims concurrency slot/generation before awaits. Resolved-session-ID turn lease is a third boundary and serializes transcript load → run → flush across routing keys. Registry absence is an explicit no-op fallback.
- Runner active-turn marker is best effort; a marker write error does not itself abort the run. Its token cleanup and delivery-ledger handoff do not establish atomic/exactly-once behavior.
- Response shaping happens before gateway transcript reconciliation. Then the delivery-policy helper returns text or None; the adapter records final-text obligation before send. Streaming/queued branches may already have delivered text.
- Final text can be ledgered and retried/redelivered; attachment/TTS paths have different helpers. Do not infer one universal delivery guarantee from final-text ledger.
- Startup separately recovers process checkpoints, interrupted turns and owed replies. Boot obligation redelivery and synthetic session resume are distinct paths. Startup-held external inbound is drained after bounded restoration.
- Async completion injection acknowledges adapter acceptance, not execution. The source explicitly documents crash-after-acceptance replay. Push adapters get synthetic internal MessageEvent; API-server may self-post.
- Cron is an independent trigger. Built-in provider calls tick, which holds retirement admission/file lock and checks ESTOP/drain/stale-code before due scan. Recurring next-run advancement happens before execution; no assertion of exactly-once side effects.
- In-process running membership, persisted execution attempt, due occurrence/run claim, durable fire claim and side-effect fence are distinct. The inventory deliberately keeps trigger/submission/fire ownership separate.
- Managed systemd topology launches restart-safe worker by scope/subprocess. Outside managed topology helper returns false and runs in process. External worker results and delivery queue are not a return into the user-message adapter task.
- Cron run_job may return before constructing AIAgent (no_agent/script/monitor/preflight). Watchdog measures inactivity, can interrupt and retain a still-running future for deferred teardown. Ephemeral agent teardown is deferred until save/delivery when caller requests it.

## Remaining coverage limits

- This is a host/service and shared-turn inventory. It does not exhaust concrete Telegram, Discord, Slack, API-server, hosted rooms, relay or other platform event/transport internals, OAuth/authenticator internals or delivery retry schedules.
- Source neighborhoods and owner function bodies were inspected for the relationships listed. Individual platform plugins, all session hygiene compressor implementations, all profile-identity backends and full SessionStore/SessionDB transaction/recovery internals remain separate deeper studies.
- Shutdown region exposes orchestration stages, not every deadline/fallback helper. Forced process death can bypass finally.
- External scheduler provider plugin implementations and all delivery queue transaction/idempotency internals were not audited. Their outer owner seams are shown with conditions; uncertain outcomes must remain visible.
- Graph edges include caller relationships, data dependencies, background spawn and logical stage transitions. `transition` edges are deliberately not direct helper-to-helper calls.
- Static validation checked unique inventory IDs, unique (from,to,kind), bridge existence, source file existence and line bounds; this is not runtime validation.


## Source-grounded observations

- The CLI config loader is distinct from the shared config loader: it applies CLI defaults/file/environment expansion/managed overlay and mirrors selected settings to the tool environment. Do not merge these two loaders into an invented single lifecycle.
- Credential admission happens before each CLI chat. AuthError-only configured fallback is separate from inference-call retry/fallback. Changed credentials/route/model retire the existing agent.
- Plugin discovery joins background loading before the tool snapshot. MCP discovery has a bounded wait and may not have finished at agent construction. Built-in discovery happens at model_tools module import.
- Tool registry availability filtering, selected toolsets, schema rewriting, sanitization and tool-search progressive disclosure are separate boundaries.
- Prompt tiers use stable/context/volatile cache bands, but volatile does not mean freshly regenerated every turn. Pinned skill bodies resolve once per agent lifecycle; the skill index describes discoverable skills.
- Project instructions choose the first nonempty supported family, rather than loading all instruction conventions together.
- Startup resume follows eligible compression descendants and loads separate model/display projections. Mid-session resume retargets the agent and metadata. Session restore does not resume a provider call.
- New-session rotation includes old-session best-effort persistence and ordered external-memory boundary work. Branch creation precedes parent end, but transcript copy is best effort.
- Undo/retry publish in-memory truncation only after durable rewind succeeds when a store exists. Undo emits a rewound memory switch; retry rejects unsafe replay.

## Limits and omitted areas

- These are source-inspected surface contracts. Full implementations of each provider OAuth flow, credential pool persistence, plugin lifecycle, MCP handshake/transport and external skill trust policy remain deeper-study areas.
- Execution environment creation is lazy in `tools/terminal_tool.py:_acquire_env` (line 1182), separate from prompt environment hints. This expansion deliberately leaves that node to the tool/environment workstream to avoid duplicate ownership.
- Session export, worktree management, titles/search and checkpoint rollback are real supported surfaces but are not fully expanded in this slice. The durable SQLite implementation and its crash/restart guarantees need their own study.
- Resource availability can change after initialization; no arrow claims a forever-frozen registry. Tool schema cache and snapshot generation exist, but full refresh invalidation races were not audited.
- Branch transcript copy and new-session/close cleanup contain suppressed exceptions. Do not label them atomic all-or-nothing or guaranteed crash recovery.
- The pinned original context lifecycle document was not changed. Only temporary integration artifacts were written.

## Review limits

This is a surface coverage expansion from observed orchestration bodies. No Hermes runtime, providers, real tools, tests or services were executed. It is not a proof of recoverability, side-effect idempotency or provider-specific transport behavior.

Existing provider API and tool environment nodes stand for actual integrations. This study does not expand every provider protocol, registry tool implementation, approval backend, Relay integration or memory-provider implementation. Compression internals additionally contain micro-compaction, durable cooldowns/anti-thrash counters, manual policies, long-context thresholds and fallback details which remain follow-up areas. The admission/liveness and lazy terminal environment regions record those boundaries separately.

Node/edge source line bounds and node ID uniqueness were checked against local source. Line validity alone is not semantic validation; enclosing owner bodies listed above were read and the relationships use explicit conditions for branch alternatives.

## Admission, liveness and environment

SQLite turn admission is conditional on a bound, enabled store. Holder-qualified
renewal prevents lease loss from becoming an unnoticed second writer; progress
monitoring samples activity separately because renewing a lease is not progress.
Contended admission reloads current durable history before execution. Cleanup
deactivates renewal before bounded timer cancellation and clears only its own
interrupt before releasing the holder. A soft interrupted wait may carry an
unpersisted message to the next turn; a hard stop cancels it.

Terminal environments are acquired lazily after a tool execution plan, using
per-task creation locking and a reusable cache. Prompt environment hints do not
create a sandbox. Full backend implementations and resource teardown remain
behind the execution-environment boundary.
